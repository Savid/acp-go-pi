## Credential boundary

Provider credentials reach a session only by explicit injection — environment
options or seeded files — into that session's isolated pi agent directory.
They are never mirrored into the session store, never logged, and never read
from the operator's real pi home. By default the adapter does not log secrets,
prompt text, tool payloads, or raw pi event bodies.

## Environment scrubbing

Every pi child runs with a scrubbed environment: ambient shell variables are
not inherited. pi treats ambient provider keys as live authentication, so
without scrubbing an exported `OPENAI_API_KEY` would silently become a
session's identity. Scrubbing makes every credential path deliberate. Each
session also runs with pi's phone-home behavior pinned off (`PI_OFFLINE=1`),
so no update checks or telemetry leave the machine from the pi child.

## Permission enforcement

The adapter's bridge extension is the session's permission system — pi ships
none natively — and it is deterministically the only extension loaded besides
the adapter's MCP client. In the default `ask` mode every gated tool call
requires an ACP permission decision, a cancelled dialog fails closed as a
deny, and `allow` mode is only ever explicit per session — see
[Permissions](/docs/features/permissions).

## Process isolation

Each session's pi process runs in its own isolated agent directory under the
`WithScratchDir` parent, so sessions share no config, auth, or session files.
Linux launches each native root through a private embedded subreaper. Its
control-descriptor boundary kills and reaps descendants, including processes
that call `setsid`. Windows starts the root suspended, assigns it to a
kill-on-close Job Object, and only then resumes it. These platforms report
`containment=authoritative`.

FreeBSD, OpenBSD, and unsupported platforms reject native startup. Darwin also
rejects startup by default. `WithDarwinBestEffortContainment` or
`-darwin-best-effort-containment` is an explicit operator acceptance of a
weaker boundary; it reports `containment=best_effort` and prints a warning.
The option is invalid on every other platform.

Darwin best-effort places the direct child in a new process group, installs one
immediate waiter that always reaps it, captures that original PGID once, and
runs a single memoized cleanup ladder. Cleanup sends TERM, waits up to 500 ms,
then sends KILL and polls only the captured PGID for at most five seconds in
total. Unexpected TERM, probe, or KILL errors force-kill the direct child and
join its sole waiter within the same deadline. The first `ESRCH` is terminal
and no later signal is sent to that numeric PGID. Success requires the direct
child to be reaped and the original group to be absent.

That result is not whole-tree quiescence. A descendant can call `setsid`,
leave the group, and survive. A numeric PGID can be reused before it is first
observed absent, so group signalling can affect unrelated work. Native-root
admission permits bound wrapper-managed roots; they do not bound provider work
that escaped. Darwin therefore emits no provider-descendant inventory
snapshot, including zero.

Every Darwin launch receives exact `ACP_GO_PI_RUNTIME_ID` and
`ACP_GO_PI_SCRATCH_ROOT` markers after environment scrubbing and writes a
strict current record in a `0700` registry; records are non-symlink regular
files at `0600` and limited to 4096 current entries. Only `group_absent`
records older than 30 days expire before a new launch. `running` and
`cleanup_incomplete` records remain indefinitely so unresolved work stays
actionable. Each real native generation has its own `0700` root and 128-bit
runtime id. Markers are correlation hints, not ownership: descendants can
inherit them, erase them, or outlive their original group. An empty marker
scan is not evidence that every descendant is absent.

The operator cleanup command requires a chosen runtime id plus `-force`. Its
fixed five-second deadline starts before the first process enumeration and
bounds the 500 ms TERM grace, KILL phase, and final scan. It scans only
same-UID processes, correlates both exact markers, revalidates PID, start time,
UID, and markers immediately before each signal, and signals individual PIDs
only. PID-by-PID cleanup has a PID-reuse time-of-check/time-of-use race and can
signal an unrelated reused PID; this is a collateral-signalling risk even
after revalidation. Recorded PIDs and PGIDs are never signal authority. Gone
means `ESRCH`; changed identity, unreadable identity, or scrubbed markers are
ambiguous and report-only. Cleanup rescans for candidates created during the
TERM grace period, retains the generation root on remaining or ambiguous
identities, and removes it only after repeated empty correlated scans. Even a
successful cleanup is not proof that an unmarked escaped descendant is absent.
Reaching the shared deadline is terminal even after an empty scan: cleanup
does not enumerate again, validate again, remove the generation root, or
report success.

## Input validation

MCP server declarations are validated before pi launches; unsupported
transports and invalid names are rejected up front and never reach the CLI
(see [MCP](/docs/features/mcp)). Seed-file paths are confined to the session's
agent directory — absolute paths and `..` escapes fail closed — and prompt
content that the adapter cannot forward is rejected before the turn starts
(see [Prompt streaming](/docs/core/prompt-streaming)).
