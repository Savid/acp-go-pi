## Ordinary execution

Omitting `ProcessIsolation` is the portable default. Pi runs as the adapter's
current root or non-root UID, GID, and supplementary groups; the adapter never
consults `SUDO_UID` or silently chooses another account. Ordinary startup needs
no privileged setup, identity lease, authority directory, owner/disposition
record, capability duplication, or task-vacancy proof.

Each child gets its own process handle (and a process group where the platform
supports one). Session/runtime locks and direct-child waits keep starts,
cancellation, shutdown, and reaping deterministic across Linux, Darwin,
FreeBSD, OpenBSD, and Windows. This mode reports `shared_identity`, but the name
is not an authority claim: the adapter exposes no descendant inventory, emits
no inferred zero snapshot, and does not claim whole-tree quiescence or
credential separation. A descendant that escapes the direct boundary can
survive.

The environment is captured once when the agent is constructed. Only a narrow
ordinary set such as PATH, home/user identity, temp, locale, terminal, and
Windows process variables is retained. Ambient provider credentials, loader
hooks, shell hooks, Node hooks, and adapter-private re-exec state are removed.
Explicit `WithEnv` and `WithPiEnv` overlays are the deliberate credential route
and are cloned before use. Ordinary PATH entries and configured executables may
be relative; the absolute-path rules below apply only to explicit isolation.
Every Pi child also receives adapter-managed `PI_CODING_AGENT_DIR` and
`PI_OFFLINE=1`.

## Explicit trusted-root Linux isolation

Supplying `WithProcessIsolation`, or CLI
`-process-isolation-config=/absolute/path/process-isolation.json`, selects a
different boundary. It is Linux-only, requires a trusted root supervisor and a
distinct non-root UID/GID, clears supplementary groups for Pi, and treats the
policy's `BaseEnvironment` as a complete replacement. A same-identity request,
invalid field, absent authority, wrong platform, or launch failure is terminal;
there is no ordinary, same-identity-supervisor, or Darwin fallback.

The CLI policy must be a root-owned, single-link mode-`0600` regular file
resolved componentwise from `/` without following symlinks. The configured
account has a same-name private primary group, no supplementary groups, and a
target-owned mode-`0700` home below protected root-owned ancestry. PATH entries
must be existing canonical absolute directories. Inherited variables are a
closed allowlist and may not include identity, loader, interpreter,
XDG/native-home, or adapter-private state.

The Linux guardian/liveness pair are trusted-root subreapers created before Pi.
They retain the required authority leases, pass Pi none of their launch,
control, proof, or lock descriptors, and adopt, kill, and reap descendants to
kernel `ECHILD` before publishing authoritative completion. Either trusted peer
can finish cleanup if the other is killed. The direct Pi child alone receives
the target identity.

Authority lives at `/var/lib/acp-go/agent-identities` on a persistent local
filesystem shared by every participant using the same numeric identity pool.
Permanent UID and domain lock inodes are never replaced. Domain records bind
the boot, PID/user namespaces, UID/GID mappings, and procfs visibility. Borrowed
capabilities must name the canonical inodes and already carry the required
whole-file flock; Linux strictly parses `/proc/self/fdinfo/<fd>` and refuses
missing, ambiguous, partial-range, wrong-mode, or wrong-inode locks. Pi inherits
no capability descriptor.

Standalone authority additionally binds the owner ID and exact state-root
path/device/inode, validates owner and disposition records, and proves the
target identity vacant before publishing `ACTIVE`. The state root is dedicated,
outside the authority root, target-owned mode `0700`, and reached without
symlinks or writable foreign ancestry. Unknown or incomplete state fails
closed. An `ErrProcessContainmentIncomplete` result requires the host to retain
or quarantine resources that native work may still reach.

## Durable provider authentication

Provider auth is available only in ordinary mode with both `WithHome` and
`WithProviderAuthRoot`. The durable home is service-owned Pi state; it must
never be the operator's real `~/.pi`. Pi's native `AuthStorage` and
cross-process credential lock own the credential file. The adapter ledger is a
separate mode-`0700` tree of mode-`0600` values-free records and is scoped by
the durable home.

The seven broker legs never return a credential value. Catalog text and URLs
are normalized and bounded; loopback-only browser flows, executable shell-key
variants, stale connection generations, and late completions are refused.
Browser shims prevent native launchers from opening a local desktop behind the
host's login UX. Per-flow and per-provider gates serialize callback,
disconnect, cancellation, and session-close races. Session-store mirroring
excludes credentials and agent configuration.

An explicit distinct-identity policy with a durable provider-auth home is
refused because a safe cross-identity credential-delivery design is not proven.
The adapter never weakens isolation to expose Connect.

## Darwin best effort

`WithDarwinBestEffortContainment` is a separate embedded-only opt-in, not the
ordinary default and never a fallback for explicit isolation. It reaps the
direct child and sends a bounded TERM-to-KILL ladder to the captured original
process group. A descendant can call `setsid`, leave that group, and survive;
numeric PGID reuse can also affect unrelated work. The mode therefore emits a
warning, reports `best_effort`, and exposes no descendant inventory.

Best-effort launches retain strict runtime records and generation roots for
operator diagnosis. `acp-go-pi containment diagnose` is read-only. Forced
cleanup revalidates same-UID process markers before signalling, but PID reuse
still creates a collateral-signalling race and even successful cleanup is not
proof that an unmarked escaped descendant is absent.

## Permission and input boundaries

The wrapper-owned bridge is Pi's permission system. In default `ask` mode every
gated tool call requires an ACP permission decision and cancelled dialogs deny;
`allow` must be explicit per session. MCP declarations and seed paths are
validated before launch.

Local prompt-image reads exist only when a host configures
`WithInputHandoffRoot`. Files are opened relative to that directory without
following escapes, must be regular, are byte-bounded, and must match the
declared SHA-256. The adapter never writes, moves, or removes host handoff
files, and never fetches a remote URI.
