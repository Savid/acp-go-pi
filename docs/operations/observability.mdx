## Telemetry wiring

Embedded hosts supply OpenTelemetry providers with `WithTracerProvider`,
`WithMeterProvider`, and `WithTextMapPropagator`. The standalone binary
includes OpenTelemetry exporter support and configures traces, metrics, and
logs from standard `OTEL_*` environment variables. Providers a host passes
stay owned by the host, including `ForceFlush` and `Shutdown`.

Logs go to stderr so stdout stays reserved for ACP frames; enable debug
logging with `-debug` (`WithLogger` for a custom logger). Telemetry records
lifecycle timing, request outcomes, and counters, and by default avoids
recording prompt text, tool inputs, tool outputs, and raw pi event bodies.

## Native-boundary failures

Managed hosts should classify errors with `errors.Is`. An
`ErrHostAuthorityUnavailable` result stops further managed native admission;
`ErrContainmentIncomplete` means terminality or tree ownership is uncertain;
and `ErrNativeTreeBusy` means reclaim was refused before mutation because a
process handle is still live. The adapter logs operation context without
recording authority environment values, prompt text, tool data, or provider
messages.

Ordinary execution reports no whole-containment proof. With a host authority,
the lifecycle capability advertises process containment, and terminal events
are published only after the authority's `Wait` result settles the generation.

## Diagnosing turn failures

A failed prompt returns a `pi_turn_failed` error whose `cause` tells you where
to look. The [failure contract](/docs/reference/acp-methods) defines the full
shape; use the `cause` to route the investigation:

| Cause | First thing to check |
| --- | --- |
| `process_exit` | The `message` carries the bounded exit status and final stderr line naming the cause. Logs record only the fixed `process_exit` classification and stage. Confirm the `pi` CLI is installed and is version 0.80.6+. |
| `transport` | A stream broke mid-turn; check for client disconnects or a pi process killed out from under the adapter. |
| `provider` | pi reported a provider error — a missing or refused key, quota, or an upstream failure; check deliberate credential injection or the `_pi/auth/inventory` residence proof (ambient shell keys are scrubbed). |
| `timeout` | A `WithTurnTimeout` deadline expired; raise the bound or investigate why the turn ran long. |
| `extension` | A pi extension threw and the cycle failed closed. The wire message is fixed and carries no detail; the extension path, the native event name, and the thrown text are not published and not logged, because an extension's thrown text can carry tool input. Reproduce with the raw-event opt-in if you need the native record. |

A failure **away from** a prompt turn never uses this shape. Session
establishment, restore, a poisoned session, and every unclassified handler
fault answer `-32603` with one closed token and no cause text at all: the
reason is in the adapter log, not on the wire. The tokens, the
`pi_session_poisoned` `cause` vocabulary, and the `pi_internal_failure` `class`
are listed under
[Off-prompt internal errors](/docs/reference/acp-methods). A native session
start that fails is `{"error":"pi_internal_failure","class":"native_start"}`,
so grep the log for `pi session start failed` to see which stage broke.

<Note>
A user cancel that coincides with a `WithTurnTimeout` expiry resolves as a
successful `cancelled` response, not a `timeout` failure. If you expect
timeouts but see cancellations, the client is cancelling first.
</Note>

## Reading the adapter log

The adapter log is deliberately classification-only. It records fixed failure
classes, safe session/generation identifiers, and adapter stages; it never
records native stderr, provider text, user/tool content, arbitrary event names,
panic payloads, or client/action error strings. Bounded native causes remain on
their documented wire error surface. Install a logger with `WithLogger`; the
standalone binary writes those structured classifications to stderr.
