The adapter ships as both an installable CLI and an importable Go package.

## Install the CLI

Install the standalone ACP subprocess binary:

```sh
go install github.com/savid/acp-go-pi/cmd/acp-go-pi@latest
```

The `acp-go-pi` binary speaks ACP over stdin/stdout; an ACP host launches it as
a subprocess rather than running it as a human-facing chat UI.

## Add the library

To embed the adapter in a Go host, add the module and call `piacp.Serve`:

```sh
go get github.com/savid/acp-go-pi
```

## Build from a checkout

```sh
go build ./cmd/acp-go-pi
```

## Locating the pi CLI

The adapter launches `pi` from `PATH` unless a host provides `-path`
(`WithExecutablePath`). Use `-scratch-dir` (`WithScratchDir`) to choose the
parent directory under which the adapter creates ephemeral session state. By
default each session receives a private Pi agent directory. Configure `-home`
only when the instance needs a durable Pi-native credential residence, such as
for the provider-auth broker; never point it at the operator's real `~/.pi`.
The launched CLI must be pi **0.80.6 or newer**; the adapter probes
`pi --version` at startup and fails fast on older builds. Install pi itself
from npm:

```sh
npm install -g @earendil-works/pi-coding-agent
```

## Embedded host authority

Ordinary execution needs no privileged setup. An embedded service that needs a
host-enforced native boundary supplies <code>WithHostAuthority</code>; the
authority itself owns executable validation, tree preparation, process
containment, and reclaim. It cannot be configured through the CLI.

A nil or unusable authority is refused during initialization, before a probe
tree or Pi process is created. See [Run modes](/docs/get-started/run-modes) for
the managed lifecycle.
