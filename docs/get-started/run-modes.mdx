---
title: "Run Modes"
description: "Choose between the standalone binary and embedding the adapter directly in your Go host"
---

The adapter offers the same behavior through two entry points. Pick by where the
ACP transport lives: use the standalone binary when an editor or host spawns a
subprocess and pipes JSON-RPC over stdio, and embed `Serve` when your host owns
the reader/writer streams directly.

## Standalone

Standalone native mode is Linux-only. The root supervisor must receive
`-process-isolation-config=/absolute/path/process-isolation.json`; the strict
file schema, account/home checks, closed environment, and explicit
`inheritEnvironment` behavior are documented in the
[CLI reference](/docs/reference/cli). `-version` and Darwin containment
diagnostics do not require the policy. There is no Darwin or Windows
standalone-launch fallback.

`acp-go-pi` is launched by an ACP client, which drives it over stdin/stdout.
stdout carries ACP JSON-RPC only; diagnostics go to stderr (and `-debug` when
present).

```sh
acp-go-pi -process-isolation-config /etc/acp-go/pi-isolation.json -path /usr/local/bin/pi -scratch-dir /tmp/pi-scratch -model openai/gpt-4o
```

## Embedded

`Serve` runs the agent against reader/writer streams you supply, so your host
can back the transport with any pipe, socket, or in-memory buffer:

```go
err := piacp.Serve(ctx, input, output,
	piacp.WithExecutablePath("/usr/local/bin/pi"),
	piacp.WithProcessIsolation(piacp.ProcessIsolation{UID: 20001, GID: 20001, BaseEnvironment: isolationEnvironment}),
	piacp.WithScratchDir("/tmp/pi-scratch"),
	piacp.WithDefaultModel("openai/gpt-4o"),
)
```

Every serve-mode flag has an option equivalent:

| Flag | Option |
| --- | --- |
| `-path` | `WithExecutablePath` |
| `-scratch-dir` | `WithScratchDir` |
| `-model` | `WithDefaultModel` |
| `-seed-file` | `WithSeedFiles` |
| `-process-isolation-config` | constructs `WithProcessIsolation` |

Embed-only options carry no flag. Use `WithSessionStore` when the host wants
durable session storage, plus `WithEnv` for credential injection,
`WithTurnTimeout`, `WithConcurrencyLimits`, and the
OpenTelemetry providers. See the [Go API reference](/docs/reference/go-api)
for the full catalog.

The standalone binary is Linux-only. Embedded hosts may explicitly select
Darwin best-effort containment through `WithDarwinBestEffortContainment` and
receive the selected mode through `Agent.ContainmentMode`,
`RuntimeResourceHooks.ObserveContainment`, structured logs, and the
`acp_go_pi.runtime.containment` metric. Linux remains authoritative. Windows is
unavailable for native launch because the mandatory Unix UID/GID identity
boundary cannot be applied; cross-compilation proves only that refusal path
builds, not runtime support. FreeBSD, OpenBSD, and unsupported platforms also
remain unavailable.
