---
title: "Session Store"
description: "Wire a durable store so pi sessions survive beyond their isolated session directories"
---

By default a session's pi session file lives only in that session's isolated
directory. Provide a `SessionStore` when the host needs sessions to resume
from its own storage — for example a database or object store on a different
machine.

## Wiring a store

Install a store with `WithSessionStore`; bound the reads used during resume
with `WithSessionStoreLoadTimeout`. A ready-made in-memory implementation
ships for tests and small hosts:

```go
store := piacp.NewInMemorySessionStore()

err := piacp.Serve(ctx, input, output,
	piacp.WithSessionStore(store),
	piacp.WithSessionStoreLoadTimeout(5*time.Second),
)
```

After each native `agent_settled` fence the adapter appends the session file's new JSONL rows
to the store verbatim — the raw native bytes, header row first — backs
`session/list` from the store, and hydrates stored rows back into an isolated
session directory when the local file is missing. Because the ACP session id
is pi's own session UUID (it lives in the header row), a restored session
keeps its id and full history.

The fence applies to natively settled success, provider-error, and explicit
user-cancel turns: their durable state is mirrored before the ACP terminal
result. For cancellation, pi's `agent_settled` must cross the response barrier
before abort acknowledgement; after process-tree containment succeeds, the
adapter appends the resulting aborted assistant row before returning
`cancelled`. A timeout, transport/process failure, or escalated cancellation
that never reaches `agent_settled` preserves the prior committed mirror and
never publishes partial bytes.

## The store contract

The format constant and key type are stable public identifiers:

```go
const SessionStoreFormat = "pi-session-jsonl-v1"

type SessionKey struct {
	SessionID string
	Subpath   string
}
```

A store implements six methods:

| Method | Role |
| --- | --- |
| `Append` | Append session JSONL rows for a key. |
| `Load` | Read all rows for a key. |
| `Replace` | Atomically replace a full generation of a session's files. |
| `Delete` | Remove a key (and its subkeys for the main key). |
| `ListSessions` | Enumerate sessions for `session/list`. |
| `ListSubkeys` | Enumerate a session's non-main subpaths. |

The main entry log uses the empty subpath (`SessionStoreMainSubpath`).
The adapter-owned `SessionStoreLifecycleSubpath` log records each durable
boundary, the exact native-row count it covers, and the accepted session
`env` and ordered `extraPathDirs` for that generation. Restore validates that
journal strictly and reconstructs omitted request values from its last record.
An explicit value, including an empty map or list, remains a lifecycle input
and can rotate the native generation. Unknown fields, malformed or unsupported
records, a missing configuration field or journal, or any mismatch between the
boundary and native row counts fails the request; native rows beyond the last
valid boundary are not hydrated.
`Replace` MUST include the main key exactly once, and MUST refuse a call whose
replacements name one key twice — two generations of one key with nothing to
say which was meant, so the whole call fails before any key is written rather
than resolving the collision by last-write-wins. Session summaries report
`UpdatedAtUnixMilli` in Unix milliseconds.

Only conversation rows and adapter-owned lifecycle boundary records are
durable. A boundary record includes session `env`, which can contain deliberate
provider credentials, so the store must protect it as secret material.
Credential and config files in the agent directory — `auth.json`,
`settings.json`, trust state — are seeded, written by pi itself, or reconciled
to the operator baseline at launch, and are never mirrored into the store.

<Note>
`WithSessionStoreLoadTimeout` bounds load and list operations during resume.
Set it when your store can hang (network round-trips), or a slow backend will
stall `session/load` and `session/resume`.
</Note>
