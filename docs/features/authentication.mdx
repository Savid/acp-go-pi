---
title: "Authentication"
description: "Inject provider credentials or connect them through Pi's durable seven-leg broker"
---

ACP agent authentication and Pi provider credentials are separate surfaces.
`authenticate` is not used for Pi provider login. Hosts can inject credentials
explicitly, or enable Pi's `_pi/auth/*` extension broker in ordinary execution.

## Enable provider auth

Configure both a durable Pi-native home and a separate durable ledger root:

```go
agent := piacp.NewAgent(
	piacp.WithHome("/var/lib/my-host/pi-home"),
	piacp.WithProviderAuthRoot("/var/lib/my-host/pi-auth"),
)
```

The CLI equivalents are `-home` and `-provider-auth-root`. Both paths must be
owned by the service deployment, never the operator's real `~/.pi`. The home is
Pi's `PI_CODING_AGENT_DIR`, including its native `auth.json`, catalog behavior,
and cross-process credential lock. The ledger records only provider,
connection, revision, binding generation, flow identifiers, state, and
timestamps; it never stores credential values, login inputs, URLs, codes, or
native messages.

When both roots are usable, `initialize` advertises `providerAuth` with all
seven method names. No credential needs to exist first: an empty durable home
still advertises the broker so a host can show Connect. Omitting the ledger root
leaves the surface unadvertised. Supplying a ledger root without a durable home
or with an unusable path fails initialization.

Provider auth is available only in ordinary execution. Supplying
`WithHostAuthority` omits the capability and every `_pi/auth/*` request follows
the method-not-found path. Managed execution never falls back to a direct Pi
login process.

## The seven legs

| Method | Semantics |
| --- | --- |
| `_pi/auth/methods` | Executes Pi's provider catalog in the target session and returns bounded OAuth/API methods plus a fresh catalog generation. |
| `_pi/auth/authorize` | Starts or idempotently replays one session/provider/connection flow after validating the catalog generation and authorization request id. |
| `_pi/auth/callback` | Supplies the bounded paste-back value for callback-style OAuth and completes the native login. |
| `_pi/auth/status` | Returns the closed pending/authenticated/failed/cancelled state for a flow without exposing native secret text. |
| `_pi/auth/cancel` | Cancels the addressed flow and its in-flight native exchange. |
| `_pi/auth/inventory` | Probes native residence and combines it with the values-free ledger, returning only confirmed-present, confirmed-absent, or not-confirmed proof. |
| `_pi/auth/disconnect` | Deletes exactly one provider through Pi's native `AuthStorage`, fenced by connection id and binding generation, then records confirmed absence. |

There is deliberately no credential-return leg and no injection key. OAuth and
API-key material travels only between the host dialog, the wrapper-owned Pi
bridge, and Pi's native `AuthStorage`; it is never returned through ACP. Login
URLs and labels are normalized and bounded, loopback-only flows and executable
shell credentials are refused, and browser-launcher shims prevent the native
child from opening the operator's desktop browser behind the host's UX.

Per-provider slot gates serialize credential writes and disconnects. Flow
admission also fences duplicate callbacks, session close, cancellation, and
authorize replays so a late completion cannot resurrect a removed binding.

## Explicit credential injection

Ordinary mode captures a narrow base environment once and scrubs ambient
provider keys, `NODE_OPTIONS`, shell hooks, loader variables, and adapter-private
state. Pass deliberate provider variables with `WithEnv` for all sessions or
`WithPiEnv` for one session. Explicit maps still reject invalid names and
process-hijack keys. A `PATH` in `WithEnv` sets the static native base search
path; `WithPiEnv` rejects `PATH`, and `WithPiExtraPathDirs` prepends ordered
executable directories ahead of that base.

For file-backed credentials, seed Pi's `auth.json` into an ephemeral session:

```go
err := piacp.Serve(ctx, input, output,
	piacp.WithSeedFiles(map[string]string{
		"auth.json": authJSON,
	}),
)
```

The bundled clients expose this route as `-auth-file <hostpath>`. Seeded
credential files and agent-directory configuration are excluded from session
mirroring. Session-scoped environment values are part of the durable lifecycle
record, including any credentials deliberately supplied there, so protect the
session store accordingly. Brokered credentials instead stay in the explicitly
configured durable Pi home.
