---
title: "Authentication"
description: "How provider credentials enter isolated pi sessions"
---

ACP agent authentication and pi provider credentials are separate surfaces.
This adapter advertises no ACP auth methods. A pi session receives provider
credentials only through an explicit environment or seeded file chosen by the
host.

## Standalone credential input

The standalone root supervisor never forwards its ambient environment. To pass
a provider API-key variable, name it explicitly in `inheritEnvironment` in the
root-owned `-process-isolation-config` policy. The variable must be present in
the supervisor environment or startup fails. Identity, path, loader,
XDG/native-home, and adapter-private variables cannot be inherited.

File-backed credentials enter through `-seed-file
auth.json=<hostpath>`. The adapter reads that explicitly named file before
launch and writes it into each isolated session agent directory. No standalone
path reads root `HOME`, root pi config, or an unlisted root credential.

## No ACP auth methods

`initialize` reports `authMethods: []`. A host never calls `authenticate`
against this adapter, and ACP `logout` is a successful no-op that does not
touch provider credentials. A missing or refused provider key inside pi is an
ordinary turn failure with cause `provider`, not an ACP auth challenge.

## Scrubbed environment

Every pi session runs in an isolated per-session agent directory with the
complete replacement environment supplied by `ProcessIsolation`. Ambient shell
variables, including provider API keys exported in the operator's shell, are
not inherited by the pi child.

Explicit environment maps accept ordinary provider variables but reject
invalid names and process-hijack keys: `PATH`, `NODE_OPTIONS`, `BASH_ENV`,
`ENV`, every `LD_*`, and every `DYLD_*`. The child-launch boundary scrubs the
same keys again as defense in depth.

## Injecting credentials

For embedded use, pass provider variables with `WithEnv` for all sessions or
`WithPiEnv` for one session. For file-backed credentials, seed pi's
`auth.json` into each isolated agent directory:

```go
err := piacp.Serve(ctx, input, output,
	piacp.WithSeedFiles(map[string]string{
		"auth.json": authJSON,
	}),
)
```

The bundled clients expose the same deliberate file path as `-auth-file
<hostpath>` and forward it as an `auth.json` seed.

## Store exclusion

Injected credentials are never written to the session store. `auth.json` and
other agent-directory config files are excluded from mirroring, so durable
session state carries conversation rows only. Prefer environment injection
where possible and seed `auth.json` only when a provider requires pi's file
format.
