---
title: "Raw Events"
description: "Opt into bounded, gap-detectable notifications of raw pi RPC events"
---

Raw events expose pi's underlying JSONL RPC events to a host that needs to
observe or debug the native protocol. They are off by default and carry no
authoritative meaning — the ACP session updates remain the source of truth.

## Enabling per session

Raw events are opt-in per session, set when creating or loading it:

```go
req := acp.NewSessionRequest{
	Cwd: cwd,
	Meta: map[string]any{
		"pi": map[string]any{
			"rawEvent": map[string]any{"enabled": true},
		},
	},
}
```

The helper `WithSessionRawEvents(true)` sets the same metadata.

## Notification shape

Notifications arrive on `_pi/rawEvent` and carry `sessionId`, `sequence`,
`source` (always `"pi"`), and `event` — the raw pi RPC event payload. The
`sequence` is per session, starts at 1, and is strictly contiguous — every event consumes
exactly one number only after its notification is delivered successfully, so a
host can detect a dropped or replaced frame by watching for a gap. A nil event
or failed notification delivery consumes no number; the next successful event
reuses the next contiguous value.

## Bounding and truncation

Payloads are capped at 64 KiB (65536 bytes) measured on the full notification
payload. An event never fails the turn. An oversized event that is delivered
still consumes its sequence and is emitted with `event` replaced by a fixed
marker:

```json
{ "truncated": true, "reason": "oversize", "maxBytes": 65536, "sizeBytes": 70000 }
```

`sizeBytes` is the byte length of the original marshalled payload. An event
that cannot be marshalled is emitted with `{ "truncated": true, "reason":
"unserializable", "maxBytes": 65536 }` (no `sizeBytes`). Because a successfully
delivered marker consumes the reserved sequence number, the stream stays
contiguous even when a frame is replaced.
